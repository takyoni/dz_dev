## Часть 1. Two Sum двумя способами

Код в `two_sum_brute.py` и `two_sum_hash.py`.

### Способ 1. В лоб

Два вложенных цикла, перебираем все пары. Сложность O(n^2).

### Способ 2. Через словарь

Идём по массиву, для каждого числа смотрим, был ли уже нужный остаток (target - число).
Если был - ответ найден, если нет - кладём число в словарь. Сложность O(n).

### Сравнение

Перебор проверяет все пары, это O(n^2). Словарь вместо второго цикла делает поиск за O(1), поэтому весь проход O(n). За это платим памятью под словарь.
На маленьких тестах разница почти не видна, а на больших словарь заметно быстрее.

Замеры с LeetCode:
- В лоб: Runtime 1743 ms, Memory 19.7 MB
- Словарь: Runtime 0 ms, Memory 20.66 MB

## Часть 2. Сначала спросил агента

Попросил агента решить Two Sum двумя способами и назвать сложность каждого.
Перебор и сложности агент дал правильно. А версию со словарём предложил такую: сначала сложить все числа в словарь, потом пройтись и для каждого искать остаток.

```python
def two_sum(nums, target):
    seen = {v: i for i, v in enumerate(nums)}
    for i, num in enumerate(nums):
        if target - num in seen:
            return [i, seen[target - num]]
```

И уверенно сказал, что это O(n) и всё верно.

Проверил на nums = [3, 2, 4], target = 6. Словарь получается {3:0, 2:1, 4:2}.
На первом числе 3 остаток тоже 3, он есть в словаре под индексом 0, и возвращается [0, 0] - то есть одно и то же число дважды. Правильный ответ [1, 2].

Вывод: агент выдал красивый, но неправильный код. Сложность назвал верно, а само решение ломается, когда остаток совпадает с самим числом. Правильно - проверять остаток до того, как положить число в словарь (так и сделано в two_sum_hash.py). Урок простой: ответы агента надо проверять на тестах, а не верить на слово.
